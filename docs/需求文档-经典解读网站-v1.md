# 经典解读网站 · 需求文档 v1.0

> 更新时间：2026-11-05
> 状态：需求已确认，待进入方案设计

## 一、产品定位

面向大众的"经典深读"内容平台：收录经典文章/书籍原文，配套人格化解读（如孔庆东解读钱钟书《说笑》的风格）。差异化在于**解读的人格化**——同一篇经典可由不同"解读风格"演绎，服务不同读者人群。

## 二、已确认的关键决策

| 决策项 | 结论 |
|---|---|
| 解读内容生产 | **AI 全自动生成**：按风格提示词批量生成，需建立质量审核与抽检机制 |
| 版权策略 | **暂不设限**（需自担侵权风险），产品内预留下架/替换机制 |
| 商业变现 | **暂不考虑**，仅预留会员/付费扩展字段 |
| 首批内容 | **中国现代散文 + 公版古文**，跑通后再扩展儿童经典等品类 |

## 三、内容模型（扩展性核心）

- **作品（原文）与解读分离**：一篇《说笑》是"作品"节点，下挂 N 篇解读。
- 每篇解读带两个维度标签：
  - **解读风格**：孔庆东体、钱钟书体、郑渊洁体……（可持续新增）
  - **目标读者**：成人、儿童、宝妈、青少年、老年人……（可持续新增）
- 解读内容结构化：作者背景、时代背景、逐段精读、金句摘录、延伸书单——便于模板化排版与多端复用。
- 新增风格/人群 = 新增标签与提示词，不改架构。

## 四、内容来源双通道

1. **自动检索导入（主通道）**：输入书名/文章名 → 调用公开书目 API（豆瓣、OpenLibrary、古诗文网等）→ 自动带入原文与元数据（作者、简介、封面、章节）→ AI 按选定风格+受众生成解读 → 人工（或自动规则）审核后发布。
2. **后台手工录入（辅通道）**：富文本编辑器录入原文+解读，作为 AI 质量不达标时的兜底与修正入口。

## 五、功能分期

### MVP（第一期）
- 前台：首页、作品列表、作品详情（原文+解读阅读页）、按风格/受众筛选、搜索
- 后台：作品管理、一键检索导入、AI 解读生成与编辑、发布管理
- 内容：手工/半自动填充 10~20 篇示范（现代散文+公版古文，2~3 种风格）

### 第二期
- 用户体系（注册、收藏、评论）
- AI 批量生成流水线（队列、质量评分、自动发布）
- SEO 优化、内容专题

### 第三期
- 微信小程序 + 公众号（复用同一套后端 API）
- 音频解读（朗读者场景，适合宝妈/老年人）
- 会员/付费专栏（预留字段启用）

## 六、架构原则

- **前后端分离**：后端只出 API，Web / 小程序 / 公众号共用，这是多端同步的前提。
- **内容 schema 预留扩展字段**（风格、受众、音视频引用），后期加维度不改表。
- **AI 生成管道独立成模块**：风格提示词库可插拔，未来接入新风格模型不动主流程。
- 云托管部署，可平滑扩容。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 现代作品原文收录的版权风险 | 已知晓并自担；预留一键下架/替换机制；优先扩充公版内容占比 |
| AI 全自动生成的质量与风格拟真度 | 建立风格提示词库 + 质量评分规则 + 人工抽检；AI 生成默认"待审核"可配 |
| 多端同步 | 第一天就前后端分离，API 为唯一内容出口 |
