# 经典解读网站 · 技术方案 v1.0

> 更新时间：2026-11-05
> 前置文档：《需求文档-经典解读网站-v1.md》

## 一、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | **Next.js 15 (React + TypeScript)** | SSR/SSG 对内容站 SEO 至关重要；同一套代码可同时输出 Web 与 API |
| 样式 | Tailwind CSS + shadcn/ui | 快速搭建阅读向 UI，后期换皮容易 |
| 数据库 | **PostgreSQL（云托管）** | 关系型适合"作品-解读-标签"模型；JSONB 存扩展字段，加维度不改表 |
| 文件存储 | 云对象存储 | 封面图、未来音频 |
| AI 调用 | 云服务免密钥 LLM 网关 | 无需自管 API Key，模型可切换 |
| 部署 | 云托管（Serverless 优先） | MVP 流量小按量付费，可平滑扩容 |

> 小程序/公众号三期接入时：小程序直接调用同一套 API；公众号走"文章卡片跳转 Web/小程序"，无需重写后端。

## 二、数据库设计（核心表）

```
works（作品/原文）
├─ id, title, author, dynasty_era        -- 作者、年代
├─ category        -- 现代散文 / 公版古文 / 儿童经典 ...
├─ source_type     -- manual(手工) / fetched(检索导入)
├── source_url, cover_url, intro
├─ content         -- 原文全文（富文本/Markdown）
├─ status          -- draft / published / offline(下架)
└─ created_at, updated_at

styles（解读风格字典）          -- 孔庆东体、钱钟书体、郑渊洁体…
├─ id, name, slug
└─ prompt_template    -- 该风格的 AI 提示词模板（可插拔核心）

audiences（读者人群字典）       -- 成人、儿童、宝妈、青少年、老年人…
└─ id, name, slug, prompt_suffix   -- 受众侧写提示词片段

interpretations（解读）         -- 一篇作品 × N 解读
├─ id, work_id → works
├─ style_id → styles
├─ audience_id → audiences
├─ title, summary
├─ structured_content   -- JSONB：背景介绍/逐段精读/金句/延伸书单
├─ generation_type      -- ai / manual
├─ ai_model, quality_score
├─ status               -- generating / pending_review / published / rejected
└─ created_at, updated_at

generation_jobs（AI 生成任务）
├─ id, work_id, style_id, audience_id
├─ status        -- queued / running / success / failed
├─ error, retry_count
└─ started_at, finished_at
```

要点：风格与受众是**字典表**而非写死的枚举，新增即插即用；解读的结构化内容用 JSONB，后续加"音频引用""配图"等字段不改表。

## 三、AI 生成管道

```
[输入书名/文章名]
      ↓
① 检索导入：公开书目 API（豆瓣/OpenLibrary/古诗文网）→ 自动填充
   作品元数据 + 原文（公版）或仅元数据（现代作品，正文手工/已授权粘贴）
      ↓
② 选择风格 × 受众 → 创建 generation_job
      ↓
③ 组装提示词 = styles.prompt_template（风格人格）
             + audiences.prompt_suffix（受众侧写）
             + 作品原文与元数据
      ↓
④ 调用 LLM → 输出结构化解读（JSON：背景/逐段精读/金句/书单）
      ↓
⑤ 质量规则校验：字数下限、结构完整性、敏感词、
   风格特征粗检 → 打 quality_score
      ↓
⑥ score 达标 → pending_review（可配自动发布）；不达标 → failed 可重试
      ↓
⑦ 人工在后台审阅/编辑 → published
```

设计原则：提示词模板只存在 styles 表里，运营改文案即可调风格，不发版。

## 四、API 设计（前后端分离，多端唯一出口）

**前台（公开）**
- `GET /api/works?category=&style=&audience=&q=&page=` 作品列表/筛选/搜索
- `GET /api/works/:slug` 作品详情（含原文）
- `GET /api/works/:slug/interpretations?style=&audience=` 该作品的解读列表
- `GET /api/interpretations/:id` 解读详情
- `GET /api/styles`、`GET /api/audiences` 维度字典

**后台（鉴权）**
- 作品 CRUD、批量检索导入（`POST /admin/works/import`）
- 生成任务：`POST /admin/interpretations/generate`（选作品×风格×受众）、任务列表、重试
- 解读审核/编辑/发布/下架
- 风格提示词模板编辑

## 五、页面结构

**前台**
- 首页：精选解读 + 最新发布 + 风格/人群入口
- 作品库：分类/风格/受众筛选 + 搜索
- 作品详情页：原文 + 该作品全部解读（按风格/受众切换 Tab）
- 解读阅读页：结构化排版（背景 → 逐段精读 → 金句 → 延伸书单）
- 关于页

**后台**
- 仪表盘（内容量、生成任务状态）
- 作品管理 / 检索导入 / 解读生成 / 审核队列 / 风格与人群字典管理

## 七、MVP 交付范围

1. 数据库建表 + 种子数据（3 种风格、4 类人群）
2. 前台 5 个页面（SSR + SEO meta）
3. 后台：作品 CRUD、检索导入、AI 生成、审核发布、字典管理
4. AI 管道全链路（生成→校验→审核）
5. 预置 3~5 篇示范作品走通全流程

## 八、明确不在 MVP 范围

用户注册登录、评论、收藏、支付、小程序/公众号、音频、AI 批量队列自动化。
